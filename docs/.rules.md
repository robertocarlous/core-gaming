# Breevs Hackathon Build Rules & Steps

## 1. Development Workflow

- Use **AI coding tools** to accelerate development (Cursor, Claude, GPT, etc.).
- Always **review & test AI-generated code** before merging.
- Maintain **branches & PRs** for all features.
- Commit messages: `feat:`, `fix:`, `chore:`, `docs:`, etc.

---

## 2. Build Steps

### Step 1 — Smart Contract (Core MVP)

- Define state variables (`players`, `stake`, `roundDuration`, etc.).
- Implement functions: `createGame`, `joinGame`, `startGame`, `spin`, `advanceRound`, `claimWinnings`.
- Deploy contract to **Stacks Testnet**.

### Step 2 — Frontend Integration

- Build React frontend.
- Integrate wallet connection (Hiro Wallet).
- Add UI for:
  - Creating/joining a game
  - Starting a game
  - Spinning / round progress
  - Winner announcement

### Step 3 — AI Integration Layer

- AI Narrator → frontend text feed.
- AI Fairness Analyzer → post-game validation screen.
- AI Phantom Player → backend service interacting with contract.

### Step 4 — Challenge Features

- Implement **Risk Multiplier Spins** with game logic changes.
- Add **Power-Ups** inventory system.
- Introduce **Timed Decision Pressure** (auto-elimination logic).
- Enable **AI Adversary Mode**.

### Step 5 — Deployment & Demo

- Deploy frontend + backend.
- Create README with setup instructions.
- Record 2–3 min demo video showing:
  - Problem
  - Solution
  - Gameplay demo
  - AI features

---

## 3. Rules of Good Building

- ✅ Keep MVP simple, testable, and demo-ready.
- ✅ Focus on **core mechanics first** before adding spice features.
- ✅ Document everything: smart contracts, frontend flows, AI integration.
- ✅ Test each round logic thoroughly (eliminations, winnings).
- ❌ Don’t over-rely on AI — review security-critical logic manually.

---

## 4. Hackathon Mindset

- Build fast, validate early, iterate often.
- Treat AI as your assistant, not a replacement.
- Prioritize clarity, simplicity, and impact.
- Deliver a polished **demo experience** above all.
